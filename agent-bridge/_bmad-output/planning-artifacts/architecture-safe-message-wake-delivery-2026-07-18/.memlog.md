- (constraint) PRD invariants bind: content always enters the message store; listen() is the only content drain; tmux may receive only an optional fixed content-free wake.
- (decision) Adopt queue-first advisory-wake paradigm: one shared orchestration boundary persists content before independently requesting a best-effort wake, preventing callers from treating terminal delivery as message delivery.
- (decision) Bind all direct delivery entry points to the same queueMessageThenMaybeWake policy; attemptTmuxDelivery becomes a backward-compatible wake adapter and sendKeysToPane is no longer a public arbitrary-content transport.
- (decision) The only pane payload is a module-owned constant meaning pending Neohive messages; no caller argument, sender identity, message data, task data, or watchdog data can reach tmux send-keys.
- (decision) MVP wakeability requires a live recipient, verified tmux mapping, no active listening_since, and the existing live pane safety check returning true; missing or uncertain evidence suppresses wake only.
- (decision) Recipient-scoped wake leases are additive state, atomically claimed before send-keys and coalesced while pending; claim failure or contention returns queue-only without affecting stored content.
- (decision) A wake lease is cleared when that recipient begins listen(), which proves the wake instruction has been acted on; failed send-keys releases the claim, while a successful wake remains claimed until listen().
- (decision) Queue outcome is authoritative and existing success contracts remain; wake outcome is additive observability metadata with statuses suppressed, coalesced, sent, or failed.
- (direction) Deferred: richer provider-specific idle detection, alternate wake transports, and cross-host durable wake acknowledgements unless concurrency tests prove persistence is required.
